# Бот «Калькулятор самозарплаты» — «Свой резерв», команда SND

Бот задаёт 4 вопроса и считает одинаковую сумму на каждую неделю до следующего поступления — так, как будет работать карта «Свой резерв». В конце даёт три кнопки: «Хочу такую карту», «Пройти опрос», «Посчитать заново». Команда `/stats` показывает цифры для презентации.

## Что внутри

| Файл | Что делает |
|---|---|
| `branding.py` | Название, описания, команды и текст /help |
| `calc.py` | Расчёт: разбор сумм («18к», «25 000») и дат («25.12», «2 недели»), выплаты по пятницам, текст ответа |
| `bot.py` | Диалог в Telegram (aiogram 3), кнопки, статистика |
| `api/telegram.py` | Функция Vercel для Telegram webhook |
| `setup_webhook.py` | Подготовка таблиц PostgreSQL и регистрация webhook |
| `test_calc.py` | Тесты расчёта, включая случай из портрета |
| `.env.example` | Шаблон настроек |

## Логика расчёта

1. Свободные деньги = сейчас на руках − обязательные платежи − сколько отложить.
2. Выплаты — каждую пятницу до дня поступления. Если до ближайшей пятницы больше двух дней, первая выплата приходит сразу.
3. Самозарплата = свободные деньги ÷ число выплат, с округлением вниз до 50 ₽. Остаток от округления лежит в резерве.
4. Если денег не хватает на обязательное и отложенное, бот честно говорит, сколько не хватает, и что можно изменить.

## Развёртывание на Vercel

1. Импортируйте Git-репозиторий в Vercel. Выберите **Framework Preset → Other**, укажите папку проекта с `vercel.json` как **Root Directory** и оставьте **Build Command** и **Output Directory** по умолчанию.
2. Подключите PostgreSQL, например [через Vercel Marketplace](https://vercel.com/docs/postgres). Бот использует одну базу для состояния диалогов и статистики.
3. Сгенерируйте отдельный секрет для webhook командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Добавьте переменные в **Settings → Environment Variables → Production**.

   | Переменная | Значение |
   |---|---|
   | `BOT_TOKEN` | Токен от @BotFather |
   | `WEBHOOK_SECRET` | Сгенерированный секрет |
   | `DATABASE_URL` | Строка подключения к PostgreSQL. Для Neon можно взять pooled connection string |
   | `SURVEY_URL` | Ссылка на анкету, если есть |
   | `ADMIN_IDS` | Telegram ID через запятую для доступа к `/stats` |
   | `BOT_TIMEZONE` | Часовой пояс расчётов, по умолчанию `Asia/Tomsk` |

4. Выполните production deploy. Откройте `https://ВАШ-ПРОЕКТ.vercel.app/api/telegram` в браузере. Страница должна показать `Telegram webhook` без входа в Vercel. Используйте постоянный публичный production-домен проекта. [Документация Vercel о защите деплоев](https://vercel.com/docs/deployment-protection).
5. В локальной копии проекта установите зависимости командой `python -m pip install -r requirements.txt`. Впишите в локальный `.env` те же `BOT_TOKEN`, `WEBHOOK_SECRET` и `DATABASE_URL`, что и на Vercel. Остановите старый процесс polling с этим токеном и выполните:

   ```powershell
   python setup_webhook.py https://ВАШ-ПРОЕКТ.vercel.app --import-stats stats.db
   ```

   Параметр `--import-stats stats.db` переносит историю из существующей локальной базы. Если истории нет, опустите этот параметр. Повторный импорт того же файла пропускает уже перенесённые строки. Скрипт создаст таблицы, зарегистрирует webhook и обновит оформление бота.
6. Отправьте `/start` в Telegram, пройдите четыре шага и проверьте `/stats` с аккаунта администратора. При следующих деплоях на тот же домен повторно регистрировать webhook нужно только при смене токена, секрета или базы. [Telegram Bot API](https://core.telegram.org/bots/api#setwebhook).

## Локальный запуск

1. Создайте бота в Telegram: напишите @BotFather → `/newbot` → придумайте имя, например «Свой резерв — калькулятор», и username, например `svoy_rezerv_calc_bot`. Скопируйте токен.
2. Узнайте свои Telegram ID у @userinfobot.
3. Установите Python 3.10+ и зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Скопируйте `.env.example` в `.env` и впишите токен, ссылку на анкету и ваши ID.
5. Запустите:
   ```
   python bot.py
   ```
   Бот работает, пока открыт этот терминал.
6. Проверьте тесты (по желанию): `pip install pytest` → `pytest`.

Для локального запуска с polling используйте токен тестового бота или отключите webhook через `deleteWebhook` перед запуском. Локальная статистика хранится в `stats.db`.

## Оформление

При локальном запуске и при регистрации webhook бот выставляет через Bot API название, короткое описание, описание и меню команд из `branding.py`. Вручную в @BotFather остаётся только:
- `/setuserpic` → `assets/avatar.png` (аватар);
- `/setdescriptionpic` → `assets/description_640x360.png` (картинка над описанием в пустом чате);
- `/setjoingroups` → Disable (бот только для личных чатов).

Если Telegram отклонит смену имени из-за частых изменений, в логе будет предупреждение — бот всё равно запустится.

## Как использовать в кейсе

- **Канал кампании (часть 2):** бот — канал с пользой. QR-код на него печатается на плакатах в кампусе, ссылка идёт в студенческие паблики и Telegram-каналы.
- **Добор опроса (часть 3):** кнопка «Пройти опрос» ведёт в ту же анкету. Отмечайте в методологии, что часть ответов пришла через бота.
- **Проверка спроса:** `/stats` показывает воронку «открыли → получили расчёт → нажали „Хочу такую карту“». Это поведенческие данные, а не мнение — сильный аргумент на защите. Цифры нужно брать как есть, без округления «в свою пользу».
- **Защита:** QR-код на финальном слайде. Члены жюри могут сами посчитать свою самозарплату за минуту.

## Ограничения

- При локальном запуске незаконченный расчёт сбрасывается при перезапуске. На Vercel состояние диалога и статистика сохраняются в PostgreSQL.
- Бот ничего не знает о реальных счетах — это демонстрация механики, а не банковский продукт. Об этом сказано в ответе на кнопку «Хочу такую карту».
